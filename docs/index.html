Python's re interface, the mrab-regex superset behind it, and the ECMA-262 dialect that JSON Schema and OpenAPI actually mean — one engine, the same answer on native, wasm, wasm-gc and js.

Why a second regex

MoonBit's own @string.Regex is fast and good at lexing, but it is its own grammar and stops short of ECMA-262. moonregex makes the grammar a parameter instead of a fork.

Python, by default

(?P<name>…), \A, \Z — the interface everyone already knows.

ECMA-262, for real

The grammar JSON Schema and OpenAPI define, where pattern means §22.2 and tolerates nothing else.

The regex superset

Fuzzy matching, recursion, set operations, variable-length lookbehind — gated the way mrab-regex gates them.

Shell globbing

fnmatch, Glob and GlobSet sit on the same engine, so Unicode handling is free.

Quick start

Add the module, then use the re-shaped surface on every backend.

# install
moon add moonbitstack/moonregex

# run the demo
moon run examples/tour
// the leftmost match, Python-style
match @moonregex.search(r"(\w+) (\w+)", "hello world") {
  Some(m) => println(m.group().unwrap())  // "hello world"
  None => println("no match")
}

// compile once, configure once
let rx = @moonregex.compile(
  r"[A-Z]+",
  flags=@moonregex.Flags::new(ignorecase=true),
)

Configuration, and its precedence

Every module function takes the same four knobs; they resolve in a fixed order so the result is never ambiguous.

ArgumentSetsDefault
dialect~the grammarPython
flags~the flag set@moonregex.flags
lists?named lists for \L<name>none
partial~partial matchingfalse

Precedence, highest first: an argument at the call site → the package defaults → the compiled Pattern. compile bakes the settings in; the Pattern:: methods then ignore any flags you pass and reuse what was compiled. Configure once, match reproducibly.
